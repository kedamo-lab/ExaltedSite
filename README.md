# Exalted

Минималистичный сайт сообщества в чёрно-сиреневых тонах.

## Страницы

| Страница     | Файл          | Что внутри                                  |
|--------------|---------------|---------------------------------------------|
| Главная      | `index.html`  | Hero с названием **Exalted**, блок «Кто в войсе» |
| Роли         | `roles.html`  | Озвучка · Кино · Музыка · Литература        |
| Администрация| `admins.html` | 6 админов, профили Discord                  |
| Галерея      | `gallery.html`| Видео (mp4 / YouTube), редактирование только для администраторов |

## Как запустить

Сайт работает как обычная статика — можно просто открыть `index.html`.
Но чтобы профили администрации читались **в реальном времени из Discord**, нужен сервер.

Проект устроен как **npm workspace** (`server/` — рабочая область): все зависимости
сервера ставятся одной командой из корня.

```bash
npm install   # один раз, из корня — ставит зависимости server/ (workspace)
npm start     # запуск из корня → node server/server.js
```

После этого открой `http://localhost:3000`.

## Живые профили Discord

На странице «Администрация» клик по нику открывает модалку в стиле Discord:

- аватар и баннер из Discord;
- глобальный ник, ник на сервере, статус (в сети / оффлайн);
- роли с цветами;
- активность (игра, музыка, кастомный статус);
- «в участниках с» (дата вступления).

Сервер держит бота на сервере «Exalted» и отдаёт данные через `GET /api/member/:id`.
Кэш — 45 секунд, поэтому статусы почти в реальном времени.

### Что недоступно боту

- **Интеграции** (связанные аккаунты: Spotify, Steam и т.д.) бот видеть не может
  — это доступно только владельцу аккаунта через OAuth. Блок в модалке поэтому информативный.
- **Присутствия** работают, только если у бота включены привилегированные интенты
  (`GUILD_PRESENCES` и `GUILD_MEMBERS`) в Discord Developer Portal.
  Если они выключены, сервер сам переподключится в упрощённом режиме —
  роли и дата вступления будут, а активность покажет «недоступна».

## Безопасность токена

Токен бота лежит в `server/.env` и **только там** — не в HTML и не в JS.
Этот файл игнорируется git-ом (`.gitignore`). Не публикуй его и не пересылай.

⚠️ Если токен когда-нибудь засветится в переписке или открытом репозитории —
**сразу перевыпусти его** в Discord Developer Portal (кнопка *Reset Token*).

## Галерея

Добавить или убрать видео может только **администратор**:

1. Нажми плавающую **кнопку-ключ** в правом нижнем углу (есть на всех страницах).
2. Введи пароль администратора в модалке «секретной зоны».
3. Верный пароль включает режим админа (зелёный ключ) — после этого клик по пустой ячейке
   открывает форму добавления `.mp4/.webm` или YouTube-ссылки, а у видео появляется кнопка «✕».
4. Вложения сохраняются в браузере администратора (localStorage).

Пароль в коде **не хранится** — сравнивается только его SHA-256 хеш.
Обычные посетители видят видео, но не могут их менять.

## Деплой на Render

Сервер готов к Render — и из Blueprint, и при ручном создании сервиса:

- **Корень репозитория сам по себе разворачиваемый**: root `package.json` объявляет
  `server/` как workspace, поэтому и `npm ci`, и дефолтный `npm install` в корне ставят
  зависимости сервера (express, discord.js, dotenv) автоматически.
- Порт берётся из переменной окружения (`process.env.PORT`) — задавать ничего не надо.
- В репозитории лежит манифест `render.yaml` (Blueprint) с `buildCommand: npm ci`.

### Как задеплоить

1. Запушь репозиторий на GitHub.
2. В [Render](https://render.com) → **New → Blueprint** → подключи этот репозиторий
   (или **New → Web Service**, если хочешь вручную — root-`package.json` тоже сработает).
3. **Задай секрет** `DISCORD_TOKEN`:
   Dashboard → сервис `exalted-site` → **Environment** → ключ `DISCORD_TOKEN`
   → вставь токен бота (тот же, что в `server/.env`).
4. **Manual Deploy → Deploy latest commit**.
5. Перейдя на URL вида `https://exalted-site.onrender.com`, сайт работает.

> Токен в репозиторий не коммитится (`.gitignore`). `render.yaml` лишь объявляет,
> что переменная `DISCORD_TOKEN` нужна — значение вводится руками в дашборде.

### Проверка после деплоя

- `GET /api/health` — здоровье сервера и статус бота.
- `GET /api/voice` — войс-каналы («Кто в войсе»).
- `GET /api/member/:id` — профиль администратора.

Если бот **не подключается** (токен не задан или ошибочный) — сайт всё равно работает,
просто живые данные Discord недоступны (API отдаёт `503 bot_offline`).

## Структура

```
site/                     ← корень = npm workspace (root package.json)
├── index.html, roles.html, admins.html, gallery.html
├── package.json          — workspace + скрипт start
├── package-lock.json     — единый lockfile (деплой через npm ci)
├── render.yaml           — blueprint для деплоя на Render
├── css/styles.css        — дизайн-система (токены, компоненты)
├── js/main.js            — шапка, модалки, галерея, секретная зона
├── avatar/               — аватарки администрации
├── hero-background/      — фон главной страницы
├── example/              — референс-скриншот профиля
├── icon/                 — фавикон, иконка приглашения
├── tabler/               — SVG-иконки ролей
└── server/               — workspace: Node.js + Express + Discord-бот
    ├── server.js
    ├── package.json
    └── .env              — токен бота (секрет!)
```
